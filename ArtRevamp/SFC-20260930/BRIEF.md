# SFC 전경 도트 전면 개편

2026-09-30 사용자 요청: 배경을 제외한 도트의 품질을 SFC 전성기 수준으로 전면 개편.
조사 기준 소스: `f19355f`, 브랜치: `codex/revamp`.

## 목표와 현재 상태

형태, 재질, 색, 움직임을 함께 다시 설계한다. 작은 원본에서도 기체의 방향과
장갑 면이 읽히고, 적의 종류를 실루엣으로 구분하며, 공격과 파괴가 일관된
도트 애니메이션으로 이어지는 것을 목표로 한다.

현재 **2안 선택과 첫 native 원본 묶음 채택**까지 완료됐다. 중립 기체·적 3종·엔진
2자세를 Battle/Title에 연결했다. [적용 검증 기록](adoption-review/VALIDATION.md)을 참고한다.
아래 스타일 후보 시트는 그림체와 재질을 검토하는 이미지이며, 투명 PNG 스프라이트
시트나 구현된 게임 화면이 아니다. 전체 전경 개편은 계속 진행한다.

| 검토 자료 | 판단 |
| --- | --- |
| [시안 v1](candidates/style-sheet-v1.png) | 밝은 장갑과 어두운 내부 구조의 구분은 좋다. 작은 장식선이 많아 원본 크기에서 정리할 필요가 있다. |
| [시안 v2](candidates/style-sheet-v2.png) | 사용자 선택 확정: “2안 가자”. 더 큰 색 면과 강한 외곽선이 새 제작 방향이다. 픽셀 격자, 뱅킹 자세, 포구 고정까지 합격한 원본은 아니다. |
| [전체 인벤토리](foreground-inventory.json) | 현재 크기·PPU·피벗·임포트 설정·파일 해시·직접 씬 참조를 보존한 조사 자료다. |

시안은 built-in image_gen으로 만들었다. v2의 요청에 들어간 8배 격자와 논리 해상도는
생성 지시이며, 출력이 그 조건을 정확히 만족한다는 뜻이 아니다. 두 후보 모두
1536×1024의 불투명 리뷰 이미지다. 이 시안을 잘라 축소한 파일을 완성 스프라이트로
간주하지 않는다. 실제 제작은 각 원본 크기에서 실루엣과 픽셀 배치를 다시 검수한다.

아트 채택은 `AGENTS.md` §2의 “사람(아트 디렉터) 큐레이션 합격작만” 원칙을 따른다.
스타일 선택과 실제 원본 파일의 채택을 구분한다. 승인 기록이 없는 후보는
`Assets/Art/`에 넣지 않는다.

## 현재 그림에서 확인한 문제

- 기체와 소형 적에서 작은 선과 명암 변화가 밀집한다. 장갑의 큰 면과 중요한
  방향 표식보다 잔선이 눈에 들어오는 경우가 있어 원본 크기의 인지가 어렵다.
- 기계 보스의 금속 표현과 생체 보스의 명암·윤곽 표현이 달라 통일감이 약하다.
  색 수만 줄이는 처리로는 형태와 재질의 차이를 해결할 수 없다.
- 기본 기체의 5장은 주로 엔진 변화다. 상승·하강 전용 자세가 없고 다른 두 기종은
  엔진 루프도 없다. 빠른 적과 직진 적의 5장 그림이 파일 해시까지 같다.
- 일부 보스는 루프 끝과 시작의 형태 변화가 크다. 촉수 등의 의도된 변형과
  몸체의 불필요한 흔들림을 분리해야 한다.

애니메이션 근거와 기존 코드 수정은 [ANIMATION-REVIEW.md](../../ANIMATION-REVIEW.md)에
있다. 현재 지적은 확인한 원본 접촉표와 기존 전투 캡처를 기준으로 한 아트 판단이다.
새 시안의 실제 전투 가독성이 검증됐다는 뜻은 아니다.

| 합계 | **285** | 새 자세와 상태를 추가하면 최종 파일 수는 증가할 수 있음 |

제외: 배경 PNG 52개와 공용 `px_white` 1개. 배경에는 근경/전경 패럴랙스,
별, 타이틀 키아트도 포함한다. 배경 폴더명이 아니라 화면에서 하는 역할로 구분했다.
현재 Art 아래의 PNG는 이 폴더에 있으며, SpriteAtlas는 적용 때 참조를 점검한다.
UI 레이아웃과 폰트 교체는 이 아트 묶음의 완료 조건에 포함하지 않는다.

15개 전경 파일이 기존 48색 기준을 넘고, 9개에 부분 알파가 있다.
조사 색 수는 보이는 RGBA 조합이므로 알파 차이도 별도 색으로 센다. 실드와 레이저의
부분 알파는 의도된 효과일 수 있다. 이 수치는 수동 검토 대상이며 불합격 판정이 아니다.
직접 씬 참조가 없는 파일도 런타임이나 빌더에서 쓰일 수 있어 임의로 삭제하지 않는다.

## 새 제작 기준

**픽셀과 형태.** 1배에서 주 덩어리, 부 덩어리, 포구/눈/코어가 먼저 읽혀야 한다.
계단 곡선은 반복 리듬을 정하고, 빛나는 면 주변에 무작위 한 픽셀 노이즈를 만들지 않는다.
외곽선을 전부 같은 검정으로 두껍게 둘러싸기보다 밝은 쪽과 그림자 쪽을 구분한다.
8비트 아이콘처럼 평면화하지 않고 제한된 명암 단계로 부피를 표현한다.

**팔레트.** 제안 작업 범위는 기체 16–24색, 소형 적 12–20색, 보스 24–40색이다.
기존 상한인 에셋당 48색을 유지한다. 재질별 3–4단계 명암을 기본으로 하되 무조건
색 수를 채우지 않는다. 밝은 장갑은 따뜻한 아이보리, 그림자는 청남색/보라 계열로
색상을 이동한다. 금속의 작고 단단한 반사와 생체 껍질의 둥근 면을 구분한다.
이 수치는 제작 가이드이며 SFC 하드웨어 제한을 재현한다는 의미는 아니다.

**진영과 기능.** 제안 기체는 아이보리/코발트 장갑, 청록 캐노피, 주황 엔진으로 묶는다.
적은 기계/생체/에너지 계열마다 재질을 구분하되 광원과 윤곽선 규칙을 공유한다.
탄은 흰 중심만 공유하고 외곽색·모양·이동 방향으로 아군과 위험을 구별한다.
시안의 청록 아군탄/자홍 적탄은 후보이며 실제 기존 예고색과 나란히 검토한다.
아이템이 적탄처럼 보이거나 장식 코어가 공격 예고를 흉내 내지 않도록 한다.

**애니메이션.** 프레임 수를 늘리기 전에 각 상태의 시작·정점·회복 자세를 정한다.
몸체와 포구 기준점은 고정하고 날개·촉수·배기만 필요한 만큼 움직인다. 기체 뱅킹은
루트 전체를 회전시키는 대신 보이는 장갑 면과 날개의 겹침이 달라지도록 그린다.
엔진은 자세와 독립적으로 반복하는 방향을 우선 검토한다. 공격 준비 동작은 이미
존재하는 Core 상태/이벤트에 맞추며, 예쁜 애니메이션을 위해 공격 시점을 바꾸지 않는다.
상태 신호가 없는 적에게 임의의 공격 예고를 덧붙이지 않는다.

**이펙트.** 소형 폭발은 점화→팽창→파열→잔화→소멸의 차이가 명확해야 한다.
전체 몸체를 반복해서 흰색으로 바꾸기보다 작은 밝은 코어와 제한된 파편으로 충격을
표현한다. 기본 그림은 하드 알파를 우선하고, 실드/레이저의 의도된 투명 효과는
명시적으로 구분한다. 플래시 감소 모드에서도 위험/피격 정보가 남아야 한다.

## Unity에서 지킬 기존 계약

- 화면은 640×360, PPU 16, 현재 URP / Retro AA를 유지한다. SFC식 미감을 위해
  프로젝트 전체 해상도를 임의로 낮추지 않는다.
- 실제 크기와 피벗은 `foreground-inventory.json`이 기준이다. 예: 기체 48×30,
  캡슐 10×8, 적 기본탄 6×6. 과거 규격표와 다른 큰 보스/파츠도 있으므로 강제
  일괄 리사이즈하지 않는다.
- 첫 교체는 기존 캔버스와 정렬점을 유지한다. PNG 교체 시 `.meta` GUID와 sprite
  fileID를 보존하고, 신규 자세는 고유 에셋으로 추가해 의도적으로 연결한다.
- 충돌 영역, 발사 위치, 보스 파츠 부착점과 파괴 후 잔해 위치를 그림에 겹쳐 검수한다.
  실루엣이 커져도 실제 판정이나 게임 수치를 몰래 바꾸지 않는다.
- 기존 전투 Tick 기반 재생, 일시정지, 선택 화면 정지, 풀 초기화와 감소 설정을 유지한다.
- 런타임이 쓰는 씬 참조와 `BattleSceneBuilder`의 재생성 결과를 함께 갱신한다.
  후보 검토 단계에서는 씬을 재생성하거나 생산 에셋을 덮어쓰지 않는다.

묶음 1에서 그림체가 원본 크기로 성립하는지 먼저 확인한다. 합격한 묶음부터 기존
`codex/revamp`에 적용하고 WebGL 검증 후 `rss-play`에 배포한다. 285개 전체를 교체할
때까지 사용자 테스트를 미루지 않는다. 첫 묶음의 변경 범위와 배포 상태는 적용 기록에 남긴다.

게임 적용 후에는 다음 항목을 실제 원본·캡처·재생으로 확인한다.

1. 1배에서도 방향/포구/기종이 읽히고, 2·3배에서 픽셀 경계와 규칙이 일정하다.
2. 현재 밝고 어두운 배경, 탄이 많은 장면에서도 기체·적탄·아이템을 식별한다.
3. 기체의 뱅킹과 엔진, 보스 부위의 루프에서 포구/부착점이 떠다니지 않는다.
4. 공격 준비/피격/파괴가 실제 상태와 일치하고 장식 루프가 정보를 가리지 않는다.
5. 일시정지·선택·재시작·기체 교체와 플래시 감소에서 같은 그림이 안정적으로 나온다.
6. Atlas 참조 누락/필터 변화/투명 테두리 번짐이 없고 기존 판정·게임 수치가 유지된다.

이번 Unity CLI 조사는 읽기 전용 배치로 Title/Battle의 저장된 참조와 원본 PNG를
확인했다. Editor 플레이나 브라우저 실주행은 실행하지 않았다. 실제 채택 시에는
Unity 검증 및 캡처를 추가하고 사용자 기기의 플레이 피드백을 구분해 기록한다.

첫 native 검수 묶음은 [파일럿 결과](pilot/README.md)에 별도로 기록했다.
생성 애니메이션의 몸체 흔들림을 검출해 제외했으며, 제작한 모든 프레임을 자동 채택하지
않는다. 배경 위 비교는 기존 적 크기 계산식을 적용한 정적 배치이고 판정·포구 오버레이나
실제 전투 재생 검증을 대신하지 않는다.
