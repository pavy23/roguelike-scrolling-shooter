## 2026-09-30 — 스타일 2안 확정

사용자 응답: **“2안 가자”**.

- 선택: `candidates/style-sheet-v2.png`
- SHA-256: `0c8023e62ea82424a27f360146217a5d081c99443fafafad6481a66ba66e41f2`
- 적용 범위: 배경을 제외한 기체·적·보스·탄·장애물·아이템·효과·도트 UI 아트.
- 확정 방향: 밝은 장갑과 어두운 내부 구조, 절제된 큰 명암 면, 선명한 색 대비,
  읽히는 윤곽, 기계·생체·에너지 재질의 구분.
- 시안 자체는 불투명 리뷰 시트다. 실제 크기의 투명 스프라이트와 프레임은 별도 제작한다.

이 기록으로 **스타일 선택 대기는 해소됐다**. 같은 방향을 다시 승인받지 않는다.
새 원본의 픽셀 품질, 실제 전투 가독성과 애니메이션 연속성을 확인해 제작 묶음 단위로
후속 검수를 진행한다. 기존 640×360 / PPU16과 판정·포구·파츠 기준점은 유지한다.

## 2026-09-30 — PixelLab 파일럿 전송·생성 승인

사용자 응답: **“PixelLab 전송·생성 승인”**.

승인한 질문: 이번 파일럿에서 만든 기체·적 스프라이트 후보를
`api.pixellab.ai`에 전송해 엔진·날개 등의 애니메이션을 생성한다.
기존 계정 크레딧에서 **합계 US$1 이내**만 사용하며, 새 결제·충전이나
소스 코드 전송은 하지 않는다. 이 범위의 작업에 중복 승인을 요청하지 않는다.

전송 승인 이전의 비공개 참조/후보 업로드는 자동 승인 검토에서 거절되어 실행하지
않았다. 최초 native 후보 생성에는 이미 공개 저장소에 게시된 스타일 v2만 참조했다.
사용자의 명시 승인 이후 새 기체 후보를 PixelLab 애니메이션 입력으로 사용했다.
이번 파일럿 전체 생성 전 잔액을 기준으로 한도 사용량을 보수적으로 계산한다.
전송·생성 허용은 새 원본의 최종 아트 채택과 구분해 기록한다.

## 2026-09-30 — 첫 native 묶음 채택·적용

첫 묶음의 원본 비교와 다음 단계(확정 → 게임 연결 → 전투 검증 → rss-play 배포)를
설명한 뒤 사용자 응답: **“계속 가자”**. 이 응답으로 아래 묶음의 채택·연결·검증·배포를
진행한다. 스타일 또는 같은 원본 묶음의 승인을 다시 묻지 않는다.

- 기체: `pilot/raw/starter/candidate_05.png`
- 엔진 B: `pilot/raw/starter-engine/frame_01.png` — 기체 A와 2자세 반복
- 직진 드론: `pilot/raw/drone.png`
- 고속 적: `pilot/raw/fast-v2.png`
- 포탑: `pilot/raw/turret-v2.png`

불합격한 엔진 프레임·드론 센서 루프·폭발 실험은 이 채택에 포함하지 않는다.
기존 배경·판정·게임 수치는 유지하며 뱅킹과 나머지 원본은 후속 제작이다.

## 2026-09-30 — 기본 기체 뱅킹 후보 채택

사용자 응답: **“현재후보 ㄱㄱ 그리고 다음작업”**. 직전 제시한 상승/하강 A/B
4장을 확정한다. `banking/manifest.json`의 up-A/up-B/down-A/down-B가 정확한 범위이며
파일과 해시는 `banking/adoption.json`에 기록한다. 같은 후보의 승인을 다시 묻지 않고
씬/빌더/Atlas 연결, 검증, rss-play 배포를 진행한다. 제외한 생성 결과는 채택하지 않는다.

다음 묶음인 기본탄·캡슐·소형 폭발의 제작/검수를 이어간다. 새 후보의 최종 채택은
그림을 제시한 뒤 별도로 구분하며, 아직 만들지 않은 그림의 채택으로 확대 해석하지 않는다.

## 2026-09-30 — 전투 도트 원본 제작 계속

사용자 “다음도 계속 가자”로 다음 탄/캡슐/폭발 원본 제작을 진행했다. 이 응답은 아직
보지 않은 원본의 최종 채택으로 기록하지 않는다. 텍스트 생성과 원본 검수 자료를
준비했으며 새로운 이미지 전송 범위는 자동 승인 검토 거절 후 별도 질문했다.
전송 확대에 대한 응답이 오기 전에는 해당 업로드를 진행하지 않는다.
