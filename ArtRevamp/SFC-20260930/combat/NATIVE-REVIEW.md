# 전투 도트 원본 제작 — 중간 검수

2026-09-30 사용자 “다음도 계속 가자” 지시에 따라 실제 크기 원본 제작을 시작했다.
현재는 **후보 제작·검수 단계**이며 새 탄/캡슐/폭발을 게임에 채택하지 않았다.

## 준비한 것

- 기존 아군탄 8×3, 적탄 6×6, 캡슐 10×8의 픽셀을 그대로 보존한 16×16 투명 여백
  입력 3장과 수정 영역 마스크 3장. [위치/크기 기록](controls/inputs.json).
- 텍스트만 전송해 생성한 폭발 점화 후보 **16장**, 각각 native 48×48, 부분 알파 0.
  [1배/4배 비교](review/explosion-ignition-contact.png).
- 탄·캡슐의 정확한 수정 영역과 색/형태 조건, 폭발의 확장→파열→소멸 조건을 담은
  [프롬프트 폴더](prompts/). 현재 9프레임/30fps/0.3초 게임 계약은 유지한다.
- 기존 PNG **347개 불변**, 입력 3장의 픽셀 보존, 출력 해시/알파/크기/중심과 그리드
  경계를 검사한 [read-only 감사](review/native-audit.json).
- CoreStandalone **611개 통과**, ArtGen 오프라인 **13개 통과**. Unity CLI의 마스크
  생성과 후보 비교 렌더는 중첩 실행 결과까지 성공했다. Play Mode나 브라우저 실주행은
  하지 않았으며 씬/생산 에셋을 저장하지 않았다.

도구는 Unity CLI 1.0.0-beta.11 / Editor 6000.5.3f1 / Pipeline 0.8.0-exp.1,
기존 URP다. 원시 로그/테스트 결과는 추적하지 않는 out/revamp/sfc-combat/에 보관한다.
사용자 저장이나 PlayerPrefs에 접근하지 않았다.

## 작은 탄의 native 크기를 보존하는 방법

[PixelLab 공식 API](https://api.pixellab.ai/v2/docs)의 생성/마스크 입력은 작은 캔버스
제한이 있다. 입력 16×16에 기존 픽셀을 1:1 배치하고, 정확한 원래 크기의 영역만
마스크로 지정했다. 나중에 생성된 PNG도 바이트 그대로 유지하고 Unity Sprite rect로
8×3/6×6/10×8 영역만 선택할 수 있다. 투명 여백 밖의 변화, 원본 기하, 피벗을
검수한 결과만 이 경로에 사용할 수 있다. 아직 이 생성은 실행하지 않았다.

입력 제작은 Tools/QaHarness/prepare_sfc_combat_controls.eval.cs로 재현한다.
코드가 만든 것은 영역 제어 입력과 검수 이미지이며 새 생산 도트가 아니다.
생성 후보 PNG를 축소·색 치환·알파 보정해서 합격시키지 않는다.

## 제외한 결과와 다음 검사

| 결과 | 검토 |
| --- | --- |
| 점화 후보 00–15 | 원본과 프롬프트를 보존. 일부는 첫 점화치고 크거나 중심이 치우친다. 연속 프레임의 입력 선별 후보이며 아직 사람 큐레이션 합격작이 아니다 |
| 144×144 9프레임 일괄 생성 4장 | **전부 제외**. 요청한 48×48 3×3 그리드를 지키지 않고 그림이 칸 경계를 가로지르며 잘렸다. 네 반환 PNG를 다시 붙이거나 축소해 native 9프레임으로 취급하지 않는다 |
| 탄·캡슐 마스크 수정 | 외부 전송 승인 대기. 생성 호출은 실행되지 않았고 결과도 없다 |
| 점화 원본 기반 애니메이션 | 입력 전송 승인 대기. 연속 프레임은 아직 생성하지 않았다 |

API가 처리 접수 때 usage=null, 완료 시에만 실제 비용을 제공하는 경우를 확인했다.
Tools/ArtGen/artgen.py가 완료 비용도 보존하도록 수정하고, 접수 비용이 없는 경우의
회귀 검사를 추가했다. 같은 작업의 재조회로 metadata를 보완했으며 재생성 과금은 없었다.

이번 텍스트 생성 사용량은 **US$0.220000000000**, 파일럿 누적
**US$0.482163876712**다. 원본/요청/작업 ID/완료 비용과 [usage.json](usage.json)을
보존한다. 새 결제·충전이나 소스 코드 전송은 없었다.

## 외부 전송 승인 대기

탄환·적탄·캡슐 PNG/마스크를 보내는 호출은 **자동 승인 검토에서 거절되어 실행되지
않았다**. 검토 사유는 기존 전송 승인이 기체·적 후보에 한정돼 새 payload를
구체적으로 포함하지 않는다는 것이다. 2026-09-30 대화에서 아래 범위의 확대 승인을
질문했고, 응답 전에는 해당 전송이나 폭발 후보 업로드를 실행하지 않는다.

- 탄환·적탄·캡슐의 controls/ 입력·마스크 PNG.
- 위에서 검토한 폭발 후보를 사용하는 애니메이션 생성.
- 전송 목적지는 api.pixellab.ai. 기존 파일럿 누적 **US$1 이내**, 새 결제·충전 없음,
  소스 코드/사용자 저장 전송 없음. 생성 허용과 최종 아트 채택은 별개다.

그동안의 텍스트 기반 새 그림 생성은 이미지 업로드가 없는 독립 작업이었다.
승인 후 탄/캡슐 native 후보와 폭발 연속 프레임을 만들어 실제 배율·배경에서 비교하고,
원본 큐레이션을 거쳐 기존 개편 브랜치에 적용·검증·배포한다.
